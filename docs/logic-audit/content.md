## 1. Medical encyclopedia (disease, symptom, drug, part) and relations

### 1.1 Disease links to speciality, but the loop to doctors is incomplete
- **Now:** `Disease.specialities` exists (`Models/Disease.ts:48-53`) and the admin can set it (`Admin/Disease/AdminManageDiseasePage.tsx:163-174`). `getDisease` (`publicController.ts:1289-1388`) fetches **3** DoctorProfiles and 3 clinics that match those specialities. The page shows them, plus a list of speciality links.
- **Why wrong:**
  - (a) There is no "see all doctors for this condition" link. The main CTA is a dead button (#6), so the page is a dead end for conversion.
  - (b) Only the `DoctorProfile` model is queried. The speciality page (`publicController.ts:966-1160`) merges `Doctor` and `DoctorProfile`, so directory doctors appear on `/speciality/x` but never on the disease, symptom or drug pages.
  - (c) The reverse relation is missing: the speciality page does not list the diseases it treats.
  - Leaders: Zocdoc, Doctolib and Paziresh24 condition pages send users to a search pre-filtered by the matching speciality and visit reason. Practo lists "doctors for <condition>". Altibbi links Q&A and content to verified doctors.
- **Fix:** Point the primary CTA at `/speciality/<first speciality slug>` or the booking search filtered by speciality. Add a "See all N doctors" link. Reuse the speciality page's `$unionWith` pipeline for the disease, symptom and drug doctor queries. On `getSpeciality`, add `Disease.find({specialities: id, …}).limit(n)` and render it.
- **Sev:** major.

### 1.2 Related clinics include inactive clinics
- **Now:** The `Clinic.aggregate` in `getDisease` (`publicController.ts:1322-1385`) has no `$match: {active: true}` on the clinic. It also runs a lookup over every clinic before `$limit`.
- **Why wrong:** The sitemap and clinic list treat `active: true` as the rule for "public" (`publicController.ts:4410`). Here inactive or unapproved clinics are shown to patients.
- **Fix:** Add `{ $match: { active: true } }` as the first stage.
- **Sev:** major.

### 1.3 Most admin-editable medical fields are never shown
- **Now:**
  - Disease: `description`, `image`, `genderSpecific`, `expectedPrognosis`, `naturalProgression`, `pathophysiology`, `possibleComplication`.
  - Symptom: the same fields plus `part`.
  - Drug: about 18 structured fields (`sideEffects`, `pregnancyWarning`, `breastfeedingWarning`, `overdosage`, `dosageForm`, `activeIngridient`, `prescriptionStatus`, …).
  - These are all editable in admin ("توضیحات" tab) and all machine-translated (`Lib/i18n/translatableFields.ts:9-58`). The public pages render only `summary`, `aiSummary` and `content` (`Disease/DiseasePage.tsx:128-137`, `Drug/DrugPage.tsx:~117`, `Symptom/SymptomPage.tsx:~140`). `TitleTextSection` is still imported into DiseasePage and DrugPage but never used.
- **Why wrong:** Admins fill fields that nobody reads, and translation cost is spent on them. On drug pages the safety fields matter most: Drugs.com, Medscape, Halodoc and DarooYab always show side effects, pregnancy and breastfeeding warnings, and Rx status.
- **Fix (PD):** Either render them as structured sections (at minimum the drug safety fields and disease complications), or delete them from the models, admin forms and `translatableFields`. Pick one source: structured fields or free `content`.
- **Sev:** major.

### 1.4 No review or trust metadata, and an unconditional "verified" shield
- **Now:** `ListPageWideHeader.tsx:33-35` always renders a `ShieldCheckIcon` next to the disease, drug or symptom name. There is no `reviewedBy` or `lastReviewedAt` field on these models, and no MedicalCondition or Drug JSON-LD unless the admin types one by hand.
- **Why wrong:** This is a fake trust signal on medical content. Leaders (Mayo, WebMD, Altibbi) show "Medically reviewed by Dr X on <date>". Google's YMYL/E-E-A-T guidelines expect this.
- **Fix (PD):** Add `reviewedBy` (ref DoctorProfile) and `reviewedAt` to Disease, Drug, Symptom and Blog. Show the shield and the reviewer only when these are set. Auto-generate `MedicalCondition`, `Drug` and `MedicalWebPage` JSON-LD from the record.
- **Sev:** major.

### 1.5 Encyclopedia records have no draft or published state
- **Now:** Disease, Drug and Symptom have no `active` or `published` field. `getDiseases`, `getDrugs` and `getSymptoms` list everything. The sitemap filter is `{}` (`publicController.ts:4402-4404`). The admin "New" button POSTs an empty body right away (`CreateNewDiseasePopup.tsx:17-20`, and likewise `Drug/CreateDrugPopup.tsx:19-20` and `Symptom/CreateSymptomPopup.tsx:19-20`).
- **Why wrong:** Half-written or empty medical entries go live instantly. Every other public model has `active`/`isActive`/`published`.
- **Fix:** Add `published: {type: Boolean, default: false}` to all three models, filter it in the list, detail, search, sitemap and relation queries, and migrate existing records to `true`. Make the create popup ask for a name (and generate the slug) the way `CreateBlogPopup` does.
- **Sev:** major.

### 1.6 Disease `genderSpecific` enum does not match the admin options
- **Now:** The backend has `enum: genders` = `["male","female"]` (`Models/Disease.ts:58`, `BecomeDoctorRequest.ts:7`). The admin offers `male|female|none` (`Admin/Disease/AdminManageDiseasesPage.tsx:42-50`). Symptom uses the correct `genderSpicificOptions`.
- **Why wrong:** "همه" (none) can never pass validation on create. On edit it is saved only because `autoController.edit` skips validators (see 7.1). The same field ends up with different valid values depending on the path.
- **Fix:** Use `genderSpicificOptions` in `Disease.ts:58`.
- **Sev:** minor (the field is not rendered publicly anyway).

### 1.7 Drug `sameAs` cannot be saved from admin
- **Now:** The drug segment (`autoRouter.ts:566-574`) has no `editBodyMutator`. The admin form sends `sameAs` as multipart FORM (`useForm` default `parser = "FORM"`; `helpers/fetcher.ts` JSON-stringifies arrays). Mongoose then tries to cast `'["id"]'` to ObjectId and the save fails. `onePopulation` is also missing, so the default value is raw ids (this works, but the Disease and Symptom segments behave differently).
- **Fix:** Add `editBodyMutator: autoController.mutateCompoundFields(["sameAs"])` to the drug segment.
- **Sev:** major.

### 1.8 Related-drug link on the disease page
- **Now:** `Disease/DiseasePage.tsx:123` builds `/drug/${el._id}`. `getDrug` looks up by id only when `slug` does not exist (`publicController.ts:1421-1424`), so every drug with a slug returns a 404.
- **Fix:** Use `el.slug || el._id`, as every other link on the page does.
- **Sev:** major.

### 1.9 Deep links by `_id` break for records that have a slug; there is no canonical redirect
- **Now:** Every `get<Node>` handler returns a 404 when an id is used and the record has a slug (for example `publicController.ts:1197-1199` and `1293-1295`).
- **Why wrong:** Old shared links, links by id in notifications, and the admin "view" links 404 as soon as someone adds a slug.
- **Fix:** Return `{redirectTo: slug}` and have the page `permanentRedirect()` to the slug URL.
- **Sev:** minor.

### 1.10 `Part` (body part) is a layer with no public meaning
- **Now:** Model `Part`, admin section "اعضای بدن" (`adminMenu.tsx:133`), and `Symptom.part[]`. Nothing public reads it; the only backend uses are in `migrationController`. The admin label has a typo, "اهضا" (`AdminManageSymptomPage.tsx:131`).
- **Why wrong:** Admin effort with no output. Leaders (Ada, WebMD, Mayo symptom checker) use body parts as the main way to browse symptoms.
- **Fix (PD):** Either add a body-part filter or navigation to `/symptom` (`getSymptoms?part=`) and to AI triage input, or remove the section.
- **Sev:** major (PD).

### 1.11 Comments and star ratings on diseases, drugs and symptoms
- **Now:** `averageScore` and `commentCount` exist on all three, and "best" sorting uses them (`buildCommentableSort`).
- **Why wrong:** Star-rating a disease has no meaning. Drug reviews are useful (Drugs.com), but ratings on a condition are not. The list pages also never pass `sort` (`app/disease/page.tsx`, `app/drug/page.tsx` and `app/symptom/page.tsx` only forward page, search and category), so the backend sort option is dead.
- **Fix (PD):** Keep comments as Q&A (the Altibbi pattern). Drop the rating on Disease and Symptom. Either expose the sort UI or remove the option.
- **Sev:** minor.

### 1.12 Admin polish
- The disease "tag" field is labelled "لگ" (typo) at `AdminManageDiseasePage.tsx:76`.
- The admin disease list has no category, tag, slug or "#specialities" columns, so the admin cannot find diseases missing a speciality link, which is what drives 1.1. **Minor.**

## 2. Category and tag layers (taxonomy)

### 2.1 Disease has both a Category and a single "Tag"; the tag works as a coloured badge
- **Now:**
  - `Disease.category` references DiseaseCategory (slug, isActive; used as a filter on `/disease` and in the header).
  - `Disease.tag` references DiseaseTag: a **single** value with `level` (a colour name), no slug and no filter.
  - The tag appears only as a badge on `DiseaseCard.tsx:33-35`. The detail page does not show it.
  - `isActive` on DiseaseTag is ignored at render time (`publicController.ts:1272` populates without a match).
- **Why wrong:** Two classification layers where one is a colour label. The admin has to maintain both.
- **Fix (PD):** Rename DiseaseTag to "badge" (for example "common", "chronic", "urgent"), honour `isActive`, and document it. Alternatively make `tags` multi-valued with a slug and a filter. Otherwise drop it.
- **Sev:** major.

### 2.2 DrugTag: a single tag, no filter, no category
- **Now:**
  - `Drug.tag` references DrugTag (`Models/Drugtag.ts`): name, `isActive` (default false), and `order` with no default.
  - Used only as a badge in `DrugCard.tsx:33-35`. `isActive` is ignored (`publicController.ts:1409`).
  - `/drug` has no filter at all (`getDrugs` accepts only page, query and sort).
  - The header has no Drugs tab.
- **Why wrong:** The admin can classify drugs, but the classification cannot be browsed. Leaders classify drugs by therapeutic class or ATC and Rx/OTC, and list pages filter on that.
- **Fix (PD):** Turn DrugTag into a DrugCategory (slug, filterable, therapeutic class), make `prescriptionStatus` an enum (Rx/OTC), add `?category=` to `getDrugs`, and add a header tab.
- **Sev:** major.

### 2.3 SymptomCategory filters nothing
- **Now:** The header tab `hrefFor: () => "/symptom"` ignores the category (`headerCategories.ts:58`). `getSymptoms` has no category param (`publicController.ts:1168-1192`), and `app/symptom/page.tsx` does not forward one. The category is shown only as a label on the detail page.
- **Fix:** Add `category` handling to `getSymptoms` (copy it from `getDiseases`: slug or id, `isActive`) and `ListPageCategorySelector` to `SymptomsListPage`. Set `hrefFor: v => /symptom?category=${v}`.
- **Sev:** major.

### 2.4 TestCategory in the header, same problem
- **Now:** `headerCategories.ts:98` sends every category to `/test`.
- **Fix:** As 2.3, or remove the tab.
- **Sev:** minor (tests are outside this scope, but the header is in scope).

### 2.5 Blog: category route missing, categories not activatable, sort orders disagree
- **Header link to `/mag/category/<v>` returns 404.** The only blog routes are `app/mag/page.tsx` (which reads `?category=`) and `app/mag/[blogSlug]`. The breadcrumb at `Blog/BlogsPage.tsx:87-97` reads `params.nodeSlug`, a param that never exists. Fix: `hrefFor: v => /mag?category=${v}`, or add `app/mag/category/[nodeSlug]/page.tsx` (better for SEO). **Major.**
- **Sort buttons drop search and tag.** At `BlogsPage.tsx:113-121` the sort handler keeps only category. **Minor.**
- **BlogCategory has no `isActive`.** The header returns every category (`publicController.ts:263`). BlogCategory also has `title` where every other category has `name`, which is why `CategoryLike` needs both. **Minor.**
- **Categories are sorted in opposite directions.** Header: `order: 1` (`:263`). `/mag`: `order: -1` (`:368`). **Minor.**
- **BlogTag filter and display ignore `isActive`, and tags have no slug.** `getBlogs` accepts any tag id (`:356-359`) and `getBlog` populates tags without a match. The URL `?tag=<ObjectId>` is not SEO-friendly. **Minor.**
- **`Blog.preloadMedias` is never read by anything** (`Models/Blog.ts:43,82-87`), and BlogMedia is only a file library. **Minor.**
- **`BLOGS_PAGE_LIMIT = 4`** (`:321`) means four articles per page, so the pagination is very deep. **Minor.**

### 2.6 FAQ
- `Faq.name` duplicates `question`: it is editable in admin (`AdminManageFaqPage`) and never used publicly. **Minor.**
- FAQs in an inactive category still appear under "All" (`publicController.ts:2537`). **Minor.**
- No `FAQPage` JSON-LD is generated. **Minor.**

### 2.7 The "taxonomy" section is only a hub
- `app/[adminKey]/taxonomy` is a link hub (`adminMenu.tsx:232-289`), not a model, so it does not overlap the category and tag models. That is fine.
- **Problem:** none of the hub items have `access`, so staff with the "notadmin" role who have Disease access still cannot open diseaseCategory, diseaseTag, drugTag or symptomCategory. The backend segments also have no `accessLevel` (`autoRouter.ts:838-1000`), which means admin-only. The same applies to faq, blogTag, pageMeta, aboutX, testify, privacy and homeIntroduction.
- **Fix:** Give each taxonomy segment the parent's access level (for example `Disease` for diseaseCategory and diseaseTag).
- **Sev:** minor.

### 2.8 Speciality doctor counts are wrong on the public list
- **Now:** `getSpecialities` populates the `doctors` virtual (limit 15), plus `doctorsCountWithMainSpeciality + doctorsCountWithSideSpeciality` (`publicController.ts:936-947`, rendered in `Speciality/SpecialityCard.tsx:119-120`).
- **Why wrong:**
  - The virtuals have no `match: {active: true}`, so inactive profiles are counted and shown.
  - A doctor whose main speciality also appears in their `specialities` list is counted twice.
  - Directory `Doctor` rows, which do appear on the speciality page, are not counted.
- **Fix:** Add `match: { active: true }` to the virtuals and count distinct doctors across both models, reusing the facet from `getSpeciality`.
- **Sev:** major.

## 3. SEO: pageMeta, redirects, sitemaps

### 3.1 Default metadata is the create-next-app boilerplate
- **Now:** `app/layout.tsx:30-31` sets `title: "Create Next App"` and `description: "Generated by create next app"`. `toMetadata()` returns `{}` when there is no PageMeta record (`getPageMetadata.ts:38`), and node pages only look up PageMeta by slug.
- **Why wrong:** Every disease, drug, symptom, blog, doctor and clinic page that the admin has not hand-edited in "متادیتا" gets that title. The result is thousands of duplicate, meaningless titles.
- **Fix:**
  - Set a real default title with a template (`title: { default: "NoyanAI", template: "%s | NoyanAI" }`), localized.
  - In `getNodePageMetadata`, fall back to the node's own fields (name → title, summary → description, image → og:image), and set `canonical` to the slug URL.
  - Keep PageMeta as an override only.
- **Sev:** blocker.

### 3.2 PageMeta is keyed by slug, so a rename orphans it
- **Now:** PageMeta is unique on `(resourceType, slug)` (`Models/PageMeta.ts:132-135`). The editor passes `slug={data.slug}` (`AdminManageDiseasePage.tsx:206`). Nothing updates PageMeta when a slug changes (`autoController.edit`). The `resource`/`resourceModel` fields exist but are never filled or queried.
- **Fix:** Look PageMeta up by `resource` (ObjectId) for node pages, and fill it from the editor. Or, on a slug change, cascade the update to PageMeta and create a `Redirection` (old → new, 301).
- **Sev:** major.

### 3.3 Slug changes create no redirect
- **Now:** `autoController.edit` writes the new slug. Links to the old URL now 404, and the old URL stays in search indexes until the next crawl. (`grep Redirection.create` finds no results.)
- **Fix:** In a generic `editBodyMutator` (or a Mongoose pre-update hook) for slugged models, when `slug` changes, upsert `Redirection{old:/<type>/<oldSlug>, current:/<type>/<newSlug>, 301}` and collapse any chains.
- **Sev:** major.

### 3.4 Redirection matching and validation
- **Encoding:** `middleware.ts:42-44` sends `req.nextUrl.pathname`, which is percent-encoded for Persian slugs. The admin types `/disease/دیابت`, so `Redirection.findOne({old})` (`publicController.ts:848-855`) never matches. **Major.**
- **Validation:** there is no normalization (trailing slash, locale prefix, full URL vs path), no check that `old !== current`, and no loop or chain detection (`Models/Redirection.ts`). **Minor.**
- **Performance:** every page request makes an uncached (`cache: "no-store"`) backend call for redirects. That includes admin pages. **Minor** (perf).
- **Fix:** Normalize both sides with `decodeURIComponent` and strip trailing slashes when saving and when looking up. Validate in `editSchema`. Cache the redirect table in the middleware, for example with a 60-second revalidation.

### 3.5 Short links use a permanent redirect
- **Now:** `middleware.ts:39` issues `redirect(target, 301)`. The admin can edit `target`, but browsers cache a 301 indefinitely.
- **Fix:** Use 302 or 307.
- **Sev:** minor.

### 3.6 Sitemap: static languages, encyclopedia drafts, missing types
- **Locales:** hreflang alternates use the static `enabledLocales = locales` (`Components/i18n/locales.ts:98`, `helpers/sitemap.ts:74-80`, `i18n/alternates.ts:35`). The middleware uses the admin-controlled `getEnabledLocales()`. When the admin disables a language, the sitemap and `<link rel=alternate>` still advertise `/xx/...` URLs, which 307 to Persian. **Major.**
- **Drafts:** encyclopedia types have filter `{}` (`publicController.ts:4402-4404`), so they are indexed without any publish state (see 1.5).
- **Missing types:** `pharmacy` (a PageMeta node type) and `test` have no sitemap.
- **lastmod:** comes from the ObjectId creation time, because no model has `timestamps`, so edits are never signalled. **Minor.**
- **robots.txt:** there is none (`public/`, `app/`). The sitemap is not advertised, and `/notadmin` and the panels are not disallowed. Add `app/robots.ts`. **Minor.**
- **noindex:** nodes with `PageMeta.noIndex` are still listed in the sitemap. **Minor.**

## 4. Blog

### 4.1 Drafts are publicly readable
- **Now:** `getBlog` (`publicController.ts:418-447`) finds by id or slug with no `published: true`. Org-authored posts are forced to `published: false` "until an admin reviews" (`Models/Blog.ts:29-33`, `orgBlogController.ts:116,150`), but they are reachable at `/mag/<id>`. `generateMetadata` and the JSON-LD are also served for them.
- **Fix:** Add `published: true` to both lookups. For an admin preview, add a separate authenticated endpoint.
- **Sev:** blocker (unreviewed third-party medical content becomes public).

### 4.2 "Most viewed" is fake
- **Now:** `publicController.ts:378-381` sorts by `{order: 1, _id: 1}`, marked `//TODO: change this`. It is labelled `mostViewedArticles` in the UI (`Blog/BlogsMostViewed.tsx`).
- **Fix:** Add `viewCount` and increment it in `getBlog`, or use PageVisit analytics. Until then, rename the section ("Editor's picks").
- **Sev:** major.

### 4.3 The newsletter ("blogRrs") collects emails and does nothing with them
- **Now:** `BlogRRS` stores emails (`publicController.ts:402-416`). Nothing sends to them. There is no unsubscribe, and the admin segment is `all` only (`autoRouter.ts:1200`), so entries cannot be deleted or exported. There is also no RSS feed despite the name.
- **Why wrong:** This is personal data with no purpose or removal path. In Iran, SMS or Telegram channels are the normal channel, not email.
- **Fix (PD):** Wire it to a sender (or an SMS pattern) and add unsubscribe and admin removal, or remove the widget. Consider adding a real `/mag/rss.xml`.
- **Sev:** minor (PD).

### 4.4 Blog content relations and reading time
- A blog cannot be linked to a disease, speciality, drug or doctor. `related` covers blog-to-blog only, and `author` is free text.
- `readTime` is a string the admin types by hand.
- **Fix (PD):** Add `diseases[]`, `specialities[]` and `reviewedBy`. Show "doctors for this topic", following the Altibbi and Paziresh24 mag patterns. Compute `readTime` from the content.
- **Sev:** minor (PD).

## 7. Cross-cutting admin CRUD issues that affect every content section

### 7.1 Edits skip schema validation
- **Now:** `autoController.edit` calls `findByIdAndUpdate(id, body)` with no `runValidators` and no 404 (`Controllers/autoController.ts:48-54`). `editSingleton` does the same.
- **Why wrong:** The enum, `required` and custom validators are only enforced on create. Examples: disease `genderSpecific: "none"` (1.6), Advertisement `resourceModel`/`resource` pairing, PageMeta slug-required-for-node, Redirection `required`.
- **Fix:** Pass `{ runValidators: true, context: "query" }`, and return 404 when the result is null. Note that `this`-based validators (PageMeta, Advertisement) need `context: "query"` handling or a doc-level save.
- **Sev:** major.

### 7.2 Empty slug breaks the page
- **Now:** Clearing the slug input sends `slug: ""`. `unique, sparse` indexes do not skip `""`, so a second empty slug gives E11000. A record with `slug: ""` is also unreachable: the id lookup requires `slug: {$exists: false}` and `/disease/` with an empty slug is not a route.
- **Fix:** Normalize `""` to `$unset` for `slug` in a shared mutator. Validate the slug format (no `/`, no spaces), and auto-generate it from the name when it is empty.
- **Sev:** major.

### 7.3 Deletes do not cascade
- **Now:** `remove` is a hard `findByIdAndDelete` (`autoController.ts:56-62`).
- **Why wrong:** Deleting a DiseaseCategory, DiseaseTag, DrugTag, BlogCategory or BlogTag leaves dangling refs. Deleting a Disease, Drug, Symptom or Blog leaves orphaned PageMeta, comments and advertisement targets, and the old URL 404s with no redirect.
- **Fix:** Block deletion of in-use taxonomy terms ("N diseases use this category"), or null the references out. On node delete, remove the PageMeta and offer a redirect.
- **Sev:** minor.

## 8. Benchmark notes (what leaders do and what NoyanAI should copy)

- **Condition pages** (Zocdoc, Doctolib, Practo, Paziresh24): each condition page links to a booking search filtered by the treating speciality and shows the doctor count. **Copy:** a CTA with a real target, "all N doctors", and one merged doctor source (1.1, 6 in the top table).
- **Medical content trust** (Mayo, WebMD, Altibbi): "Medically reviewed by Dr X, date", structured JSON-LD, and content written or answered by verified doctors. **Copy and improve:** a reviewer field tied to a verified DoctorProfile, which fits Altibbi's model and the "Persian content gap" in the benchmark (1.4, 4.4).
- **Drug pages** (Drugs.com, Halodoc, DarooYab): structured safety sections, Rx/OTC status, therapeutic class browsing. **Copy:** render the existing fields, make DrugTag a class (1.3, 2.2).
- **Symptom browsing** (Ada, WebMD): browse by body part, then hand off to triage. **Copy:** use `Part` as the navigation and send "Inspect with AI" into triage with the symptom prefilled (1.10).
- **Claims** (the Babylon failure case): do not publish accuracy numbers without a source (top table #3).
- **Iranian context:** SEO for Persian slugs needs encoding-safe redirects (3.4). A newsletter should use SMS or Telegram rather than email (4.3).
